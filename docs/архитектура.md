# Архитектура v2

> Этап 0, 11.11.2026. Основание: `ПЛАН-ПЕРЕРАБОТКИ-v3.md` §2 и находки `docs/аудит.md`.
> Все размеры — целые миллиметры. Метры появляются только в `src/render/`.

## 1. Слои и правило зависимостей

```
electron/      оболочка: окно, IPC, файлы, бэкапы, автосохранение, корзина
src/model/     чистый TypeScript — НЕ импортирует three, react, zustand, DOM
src/store/     состояние + команды + история (импортирует model)
src/render/    three.js (импортирует model, store; не импортирует ui)
src/ui/        React (импортирует store, model; render — только через <Холст/>)
src/io/        экспорт PDF/XLSX/CSV/glTF (импортирует model; glTF — render)
```
Проверка правила — тест `архитектура.test.ts`: читает импорты `src/model/**` и падает, если там есть `three`, `react`, `zustand`.

## 2. Модель (`src/model/`)

### 2.1. Изделие (шаблон) — `product.ts`
```ts
type ИдИзделия = string;                        // 'шкаф-купе', 'тумба-мойка-600', …
interface Изделие {
  id: ИдИзделия;
  название: string;
  помещения: ТипПомещения[];                    // где показывать в каталоге: ['прихожая','спальня',…]
  категория: string;                            // 'Шкафы' | 'Кухня: нижние' | 'Техника' | …
  тип: 'корпус' | 'столешница' | 'техника' | 'мягкая' | 'стол' | 'стул' | 'свет' | 'декор' | 'проём';
  габариты: Габариты;                           // заводские
  границы: { мин: Габариты; макс: Габариты };   // обязательны — без них нет «влезает»
  крепление: 'пол' | 'стена' | 'потолок' | 'ниша';
  раскладка_по_умолчанию: Раскладка;
  материалы_по_умолчанию: Материалы;
  открывание?: Открывание[];                    // этап 2: дверь, ящик, купе, подъёмник, техника
  источник?: { лист: string; достоверность: 'точно' | 'спорно' | 'нечитаемо'; заметка?: string };
}
```
Изделия описываются данными, а не кодом. Геометрию даёт одна функция `parts()`.

### 2.2. Раскладка (свойства) — `layout.ts`
```ts
interface Раскладка {
  корпус: { плита: 16 | 18; задник: 'есть' | 'нет' | 'ХДФ'; цоколь: number; ножки: number; крыша_мм?: number };
  секции: Секция[];                             // слева направо по ширине, сумма = ширина − боковины
  фасад: { тип: 'нет' | 'распашной' | 'купе' | 'ящики' | 'подъёмник' | 'push' | 'зеркало' | 'стекло';
           створок: number | 'авто'; петли: 'слева' | 'справа' | 'попарно' | 'сверху' | 'снизу';
           ручка: { вид: 'скоба' | 'рейлинг' | 'кнопка' | 'профиль' | 'нет'; место: 'верх' | 'низ' | 'середина' | 'край' } };
}
interface Секция {
  ширина: number | 'доля';
  наполнение: {
    направление: 'снизу-вверх' | 'слева-направо';   // горизонтальные полки или вертикальные перегородки
    число: number | 'авто';                         // авто: шаг 320, перестановка 32
    тип: 'регулируемая' | 'съёмная' | 'стационарная';
    ящики?: { число: number; высота: number | 'авто' };
    штанга?: { высота: number };
  };
}
```
**Правило поворота:** раскладка задана в **локальных осях изделия** (X — ширина, Y — высота, Z — глубина, фасад смотрит в +Z). Поворот экземпляра — одна матрица поверх. Полки не могут «перевернуться»: в мировые оси их никто не пересчитывает.

### 2.3. Экземпляр — `instance.ts`
```ts
interface Экземпляр {
  id: string;
  изделие: ИдИзделия;
  помещение: string;                // id помещения
  позиция: [x: number, y: number, z: number];   // центр низа, мм, в осях помещения
  поворот: number;                  // градусы вокруг вертикали, 0 → фасад в +Z
  габариты: Габариты;
  раскладка?: Partial<Раскладка>;   // только отличия от изделия
  материалы?: Partial<Материалы>;   // корпус, фасад, столешница, ручки, …
  открыт?: boolean;
  метки?: string[];                 // 'уточнить-высоту', 'спорно:глубина' …
}
```

### 2.4. Детали — `parts.ts` (сердце модели)
```ts
function детали(изделие: Изделие, экз: Экземпляр): Деталь[];
interface Деталь {
  роль: 'боковина' | 'дно' | 'крыша' | 'полка' | 'перегородка' | 'задник' | 'цоколь'
      | 'фасад' | 'ящик-фасад' | 'ящик-короб' | 'штанга' | 'ручка' | 'столешница' | 'техника' | 'стекло' | 'зеркало';
  размер: [длина: number, ширина: number, толщина: number];    // мм — для деталировки
  кромка: { длина1: number; длина2: number; ширина1: number; ширина2: number };   // мм толщины кромки, 0 — нет
  материал: string;                                            // id материала
  локально: Матрица;                                           // в осях изделия
  форма: 'плита' | 'цилиндр' | 'модель';                        // модель — для техники (этап 5)
  подвижная?: { группа: string };                              // двери/ящики — этап 2
}
```
Одна функция кормит и 3D (`render`), и деталировку, кромку, смету (`io`). Деталировка сходится с 3D по построению. Тест сравнивает сумму площадей плит из `детали()` с ожидаемой для каждого изделия каталога.

### 2.5. Помещения — `room.ts`
```ts
interface Помещение {
  id: string;
  тип: ТипПомещения;              // 'кухня' | 'спальня' | 'гостиная' | 'детская' | 'кабинет' | 'прихожая' | 'гардеробная' | 'ванная' | 'лоджия'
  название: string;
  контур: [x: number, z: number][];   // внутренний контур по часовой, мм; прямоугольник = 4 точки, Г = 6, П = 8
  высота: number | 'неизвестна';
  толщина_стен: number;
  смещение: [x: number, z: number];   // где помещение на плане квартиры
  отметки: Отметка[];                 // всё, что на стенах: проёмы, ниши, розетки, вода, щитки, наличники
  отделка: { стены: string; пол: string; потолок?: string };
}
interface Отметка {
  id: string;
  стена: number;                   // индекс ребра контура
  вид: 'дверь' | 'окно' | 'ниша' | 'розетка' | 'выключатель' | 'вода' | 'канализация' | 'щиток' | 'короб' | 'наличник';
  от_угла: number; от_пола: number; ширина: number; высота: number; глубина?: number;
}
```
Розетки, вода и щитки с листов 10–15 становятся отметками. Валидатор (этап 4) проверяет, что шкаф не закрывает щиток, а стиралка стоит у воды.

## 3. Формат `.kitchen` v2

```json
{
  "schemaVersion": 2,
  "название": "Кв. 160",
  "создан": "…", "изменён": "…",
  "помещения": [ { "id": "п1", "тип": "гардеробная", "контур": [[0,0],[1910,0],[1910,1430],[0,1430]], "высота": 2700, … } ],
  "объекты":   [ { "id": "о1", "изделие": "шкаф-купе", "помещение": "п1", "позиция": [955,0,300], "поворот": 0,
                   "габариты": {"ш":1910,"г":600,"в":2200}, "раскладка": {…отличия…} } ],
  "настройки": { "тема": "система", "фон": "графит", "шаг_сетки": 50, "толщина_плиты": 16, "качество": "авто" }
}
```

### Миграция v1 → v2 (`migrate.ts`), по шагам
1. Прочитать как v1 существующей схемой (`lib/schema.ts`). Если не прошло — показать ошибки v1 с путём до поля, как сейчас.
2. `комната` → `помещения[0]`: `тип` = 'кухня', контур — прямоугольник `длина × ширина` с центром в нуле (v1 считала координаты от центра), `высота = высота_стен`, отделка = `обои / пол`; `фон` уходит в `настройки.фон`.
3. Каждый объект: `модуль` → `изделие` по таблице `ТАБЛИЦА_V1` (57 строк, одна на позицию каталога v1). Остальное:
   - `полок / ящиков / фасад / петли / цоколь / ножки` → `раскладка` (только отличия от изделия);
   - `цвет / материал` → `материалы.корпус` (и `.фасад`, если был фасад);
   - `подъём` у навесных → `позиция[1]`;
   - `наклон_X / наклон_Z` сохраняются в `метки` (`наклон:X=…`), в v2 наклонов нет;
   - `открыт` → `открыт`.
4. **Незнакомый модуль не пропадает:** становится изделием `свободный-корпус` с теми же габаритами, позицией и цветом, получает метку `было:<старый id>` и строку в отчёте открытия: «3 объекта не узнаны и показаны свободными корпусами».
5. Незнакомые поля верхнего уровня складываются в `_v1` и записываются обратно при сохранении, чтобы ничего не терялось.
6. До первой записи в v2 исходный файл копируется в `Бэкапы\<имя>.v1.kitchen`.

Тесты миграции: `пример-проекта.kitchen`, все файлы из `Проекты\`, синтетический файл с неизвестным модулем и лишними полями. Проверка «без потерь» — обратное сравнение числа объектов, позиций, габаритов и цветов.

## 4. Состояние и история (`src/store/`)

- Каждое изменение — **команда** `{ тип, применить(проект), отменить(проект), слить?(следующая) }`. Отдельного `начатьИзменение()` нет: забыть его невозможно.
- Перетаскивание, растягивание, поворот мышью сливаются в одну запись: `слить()` с командой того же типа и объекта в пределах одного жеста.
- Правка цифрой и правка помещения — тоже команды. `Ctrl+Z` работает всегда.
- История хранит команды, а не копии проекта: на 500 объектах это килобайты, не мегабайты.
- **Автосохранение раз в 60 с**, только если были изменения: `Проекты\.автосохранение\<имя>.kitchen` (атомарно). При запуске есть автосохранение новее файла → «Найдена несохранённая работа от 14:32. Восстановить?»
- Удаление проекта — в `Проекты\.корзина\`, не навсегда.

## 5. Рендер (`src/render/`) — проектируется отдельно в 1А-2

R3F оставляем для холста, камеры, стрелок и событий. Мебель строит императивный `SceneBuilder`:
1. `детали()` всех экземпляров → группы по ключу `форма + материал` → один `InstancedMesh` на группу; матрица экземпляра = поворот экземпляра × локальная матрица × масштаб до размера детали.
2. Все плиты — один единичный box; кромка и фаска — в шейдере (`onBeforeCompile`: затемнение у рёбер по UV); вблизи LOD с настоящей фаской.
3. Изменился один экземпляр → перезаписываются только его слоты в буферах (`setMatrixAt` + `addUpdateRange`).
4. Тени: `shadowMap.autoUpdate = false`, `needsUpdate = true` только после изменения сцены; во время перетаскивания — тень-заглушка под объектом.
5. `frameloop="demand"`; профили качества: тени, dpr, сглаживание, LOD.
6. Выбор объекта: `instanceId` → id экземпляра через таблицу слотов.

**Цель 1А-2:** 200 модулей → не больше ~60 draw calls (сейчас 3 074).

## 6. Тесты

`npm test` → `vitest run` (vitest **5.0.5**, окружение `node`). Тесты лежат рядом с кодом: `src/model/*.test.ts`. Что покрываем в 1А-1: детали каждого изделия каталога (внутри габарита, без пересечений полок, сумма секций), поворот на 0/90/180/270 не меняет `детали()` в локальных осях, авто-полки (шаг 320, перестановка 32), миграция без потерь, команды и отмена.

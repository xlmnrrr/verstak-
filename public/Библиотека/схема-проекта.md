# Формат проекта «Верстака» (бывш. «Кухня 3D») — файл `.kitchen`

> **Важно (этап 1А-1, 11.11.2026).** Приложение теперь сохраняет проекты в формате **v2** (`schemaVersion: 2`: помещения-контуры, изделия, раскладка, связи квартиры). Файлы v1, описанные ниже, по-прежнему открываются: при открытии они переводятся в v2, исходный файл копируется в `Бэкапы\<имя>.v1.kitchen`. Описание v2 — `docs/архитектура.md` §3 и §7; полная схема «для блокнота» с таблицей изделий будет в этапе 7.

> Версия схемы: **1** (`schemaVersion`).
> Этот документ — контракт между приложением и тем, кто пишет проект руками (в том числе Claude).
> Рядом лежит **`пример-проекта.kitchen`** — собранная кухня, которую можно открыть в приложении или взять за образец.
> Проверка файла описана в коде: `src/lib/schema.ts` (библиотека zod).

---

## 1. Общие правила

| Правило | Значение |
|---|---|
| Формат | обычный JSON, кодировка UTF-8, расширение файла `.kitchen` |
| Единицы | **миллиметры**, целые числа |
| Углы | градусы, целые числа, 0…359 |
| Цвета | строка `#rrggbb` |
| Позиция объекта | `[X, Y, Z]`, где **X и Z — центр объекта**, а **Y — низ объекта** (не центр!) |
| Откуда начало координат | центр комнаты на полу. X — вдоль длины, Z — вдоль ширины, Y — вверх |
| Потолка нет | задаётся только `высота_стен` |
| Обязательные поля | всё, что не помечено «необязательно». Лишние поля игнорируются |

## 2. Структура файла

```json
{
  "schemaVersion": 1,
  "название": "Моя кухня",
  "создан": "2026-11-11T12:00:00.000Z",
  "изменён": "2026-11-11T12:00:00.000Z",
  "комната": { ... },
  "объекты": [ ... ],
  "настройки": { "шаг_сетки": 50, "толщина_плиты": 16, "режим_обзора": "сверху" }
}
```

`настройки` — необязательный блок. `создан` и `изменён` — строки даты; можно ставить любые корректные.

---

## 3. Комната — объект `комната`

| Поле | Тип | Обязательно | Смысл |
|---|---|---|---|
| `длина` | число, мм | да | размер по X, минимум 500 |
| `ширина` | число, мм | да | размер по Z, минимум 500 |
| `высота_стен` | число, мм | да | высота стен, минимум 1000. Потолка нет |
| `толщина_стен` | число, мм | да | толщина стен, обычно 100–150 |
| `форма` | `"прямоугольник"` \| `"Г"` \| `"П"` | да | пока реально работает прямоугольник |
| `обои` | `#rrggbb` | да | цвет обоев |
| `пол` | `#rrggbb` | да | цвет пола |

Пример:

```json
"комната": {
  "длина": 4200, "ширина": 3000, "высота_стен": 2700, "толщина_стен": 100,
  "форма": "прямоугольник", "обои": "#cbb79a", "пол": "#8a6a4b"
}
```

Стена с координатой Z = 0 находится в центре; задняя стена проходит по `Z = -ширина/2`.
Чтобы поставить модуль «вплотную к задней стене», считай:
`Z = -ширина/2 + толщина_стен/2 + глубина_модуля/2`.

## 4. Объект — элемент массива `объекты`

| Поле | Тип | Обязательно | Смысл |
|---|---|---|---|
| `id` | строка | да | уникальный внутри файла, любой (`obj-1`) |
| `модуль` | строка | да | id из каталога (см. раздел 6) или `"свободный"` |
| `название` | строка | нет | подпись в интерфейсе |
| `позиция` | `[число, число, число]` | да | `[X центра, Y низа, Z центра]` в мм |
| `поворот` | число | да | 0…359. `0` — фасад смотрит в сторону **+Z** (на зрителя). Вращение вокруг вертикали |
| `наклон_X` | число | нет | наклон вперёд-назад, градусы (отрицательное — назад) |
| `наклон_Z` | число | нет | наклон влево-вправо, градусы |
| `открыт` | true/false | нет | показать дверцы открытыми |
| `петли` | `"слева"` \| `"справа"` \| `"сверху"` \| `"снизу"` | нет | с какой стороны петли; определяет, куда открывается дверца |
| `габариты` | `{ "ш": …, "г": …, "в": … }` | да | ширина (X), глубина (Z), высота (Y) в мм |
| `подъём` | число | нет | высота низа над полом. Для навесных это и есть подъём; для напольных — 0 |
| `цвет` | `#rrggbb` | нет | цвет фасада |
| `материал` | строка | нет | подпись материала |
| `ящиков` | число | нет | число ящиков |
| `полок` | число | нет | число полок |
| `цоколь` | число | нет | высота цоколя, мм |
| `ножки` | число | нет | высота ножек, мм |
| `вид` | строка | нет | `корпус`, `навесной`, `столешница`, `техника`, `стол`, `стул`, `проём`, `декор` |
| `фасад` | строка | нет | `нет`, `распашной`, `push`, `зеркало`, `ящики` |

Пример одного объекта:

```json
{
  "id": "obj-1",
  "модуль": "cabinet-sink-600",
  "название": "Тумба под мойку",
  "позиция": [-1200, 0, -1400],
  "поворот": 0,
  "габариты": { "ш": 600, "г": 560, "в": 720 },
  "подъём": 0,
  "цвет": "#c08a4a",
  "полок": 1,
  "цоколь": 100,
  "фасад": "распашной"
}
```

**Важно про `габариты`:** это размеры *этого* объекта. Их можно менять свободно — приложение перестроит геометрию (полки пересчитаются, фасады поделятся по ширине). Если размер выходит за границы модуля из каталога, приложение подрежет его до допустимого.

## 5. Как собрать проект вручную

1. Скопируй `пример-проекта.kitchen` рядом с собой и открой в блокноте.
2. Задай `название` и `комната` — от этого зависит, куда всё влезет.
3. Расставь `объекты`: X и Z — центр, Y — низ.
   Чтобы поставить модули в линию вплотную: следующий X = предыдущий X + (ш₁ + ш₂) / 2.
4. Сохрани файл и открой его в приложении: **Меню → «Открыть файл»**.
5. Если приложение не приняло файл — оно покажет, **какое именно поле** не так.

## 7. Правила, по которым приложение проверяет файл

- Файл обязан быть корректным JSON, иначе будет сказано: «Это не JSON: …».
- Обязательные поля должны присутствовать; сообщение указывает путь, например:
  `объекты.3.габариты.ш: Expected number, received string`.
- `длина` и `ширина` комнаты ≥ 500, `высота_стен` ≥ 1000.
- `schemaVersion` больше текущего — файл откроется, но с предупреждением.
- Незнакомые поля не ломают загрузку — они просто игнорируются.
- Отсутствующие необязательные поля заполняются значениями по умолчанию.

## 8. Числа, по которым стоит проверять свою планировку

Эти правила приложение не навязывает, но они показывают, что планировка удобная:

| Что | Норма |
|---|---|
| Рабочая поверхность (столешница) | 850–900 мм от пола |
| Проход между линией кухни и столом/стеной | не меньше 900 мм |
| Рабочий треугольник (мойка — плита — холодильник) | стороны 1200–2100 мм, сумма 3000–6600 мм |
| Навесные шкафы | низ 1400–1600 мм от пола |
| Фартук (между столешницей и верхними шкафами) | 550–600 мм |
| Дверца холодильника / посудомойки | должна открываться: 600–700 мм свободного места перед ней |
| Цоколь | 80–150 мм |

Если прислать проект на проверку — сначала считается это, а потом уже вкус.
